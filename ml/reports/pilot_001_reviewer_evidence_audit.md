# Pilot 001 Reviewer Evidence Audit (Corrected)

## Objective
To strictly audit the contextual evidence available for the 40 pilot events and classify every column within `data/processed/features/event_features_v2.parquet` according to its validity for human semantic labeling, enforcing strict project leakage and heuristic-exclusion rules.

---

## 1. EXCLUDE_LEAKAGE_OR_POST_EVENT (Spatial-Density Future Leakage)
The following spatial-density fields have known future-leakage risk (they incorporate observations across the entire dataset lifespan) and are explicitly **EXCLUDED** from human review:
- `events_local_1km`
- `events_local_5km`
- `events_local_10km`
- `events_local_7d`
- `events_local_30d`
- `thermal_density_1km`
- `thermal_density_5km`
- `thermal_density_10km`
- `thermal_detection_density`

## 5. POST-EVENT CLASSIFICATION
Our current semantic classifier is POST-EVENT. These fields aggregate the complete event lifespan. They are valid for the current post-event modeling/review task, but must be explicitly marked as post-event (and would be unusable if migrating to real-time alerting):
- `end_time`
- `duration_hours`
- `detection_count`
- `max_frp_mw`
- `mean_frp_mw`
- `median_frp_mw`
- `sum_frp_mw`
- `spatial_extent_km`
- `thermal_intensity`
- `thermal_frp_variability`
- `thermal_frp_per_detection`
- `thermal_frp_per_hour`

## 6. TEMPORAL RECURRENCE
These fields use strictly historical events occurring prior to the current event (time $t < T$).
- `events_previous_7d`
- `events_previous_30d`
- `events_previous_90d`
- `frp_previous_7d`
- `frp_previous_30d`
- `frp_previous_90d`
- `active_days_previous_7d`
- `active_days_previous_30d`
- `active_days_previous_90d`
- `time_since_previous_event_hours`

*Verification*: The implementation in `build_v2_features.py` confirms these are strictly prior historical events (Count of prior events in `[T-X, T)`).
