## Leakage Verification
The test `test_excluded_feature_rejection` in `ml/tests/test_explainability.py` explicitly injects synthetic risk (`baseline_risk_score`) and future-leaky spatial densities (`events_local_7d`). The `ObservationSummarizer` utilizes the central `validate_features` method, which is strictly hooked into the V2 `APPROVED_FEATURES` allowlist. I verified that trying to summarize these excluded features triggers an explicit pipeline failure (`ValueError`), safely intercepting downstream hallucinations. Consequently, the `adapt_inference_event` adapter strips any raw dataset metadata that does not exist on the rigorous allowlist prior to evaluation.

## Observation/Semantic Separation Verification
Through execution of a real payload, I confirmed that `OBSERVATION` records are correctly generated from the allowlisted features (e.g., `cropland_fraction_1km`, `events_previous_30d`), while the `SEMANTIC_EVIDENCE` array structurally remains empty. The phrasing in `ObservationSummarizer._format_description` is aggressively hardcoded to neutral observations ("Maximum observed FRP was...", "Event is near OSM-mapped...") and rejects causative vocabulary ("indicates", "proves", "wildfire"). These are structurally distinct datatypes in the contract and cannot be automatically conflated.

## Model Lifecycle Verification
The `ModelExplanationInterface.generate_explanation` explicitly traps the `NOT_TRAINED` state and immediately returns an empty array. No fake SHAP calculations or importance values are appended to the explanation list. The `VerificationState` defaults strictly to `MODEL_NOT_AVAILABLE`.

## Confidence Separation Verification
The single ambiguous `confidence` field was correctly deprecated in the `PredictionContract` and replaced with:
1. `model_confidence`: To be generated by calibrated algorithms in the future.
2. `evidence_confidence`: Human metadata representing the reliability of semantic evidence.
3. `data_quality`: An Enum strictly dictating the quality of the raw satellite data.

Because the model is currently `NOT_TRAINED` and independent evidence is missing, the API contract correctly surfaces `model_confidence: null` and `evidence_confidence: null`. It structurally prevents a frontend from displaying a false "80% confidence" derived from poor metadata mappings.

## Test Quality Assessment
The 64 tests represent rigorous validation. Tests explicitly verify `test_inference_adapter_leakage_feature` by ensuring that known leakage fields injected into the JSON dictionary fail to appear in the `PredictionContract.explanations` array, mimicking actual API integration paths without breaking under strict validation limits. ## Defects Found & Fixes Made
**Defect Found**: `adapt_inference_event` originally passed the entire raw Parquet dictionary (including strict exclusions like `protected_area_id` and metadata like `start_time`) into `validate_features`, triggering an immediate `ValueError` due to the pipeline's strict fail-closed nature.
**Fix**: `inference.py` was updated to gracefully intercept raw events by mapping only dictionary keys present in `APPROVED_FEATURES` down the validation channel. This allows the API to drop non-ml metadata safely, while still remaining incapable of analyzing a leakage/forbidden property (as it gets dropped rather than evaluated). `test_inference.py` was modified to correctly assert that injected leakage variables are safely excluded from the resulting `explanations` output. All tests pass.

## Remaining Limitations
The system operates exclusively as a context-wrapper for raw satellite data. It remains incapable of providing actual scientific probability distributions or causations until verified labeling begins and models are actively fitted.
